# AJAX-механики: этап 2 — фронт и подключение

Дата: 2026-10-14. Основная реализация сохранена пользователем в commit
`5dc2d74` (`[#14] Connect podcast and episode UI to browser JSON API`).
Этот отчёт также описывает исправления, выполненные после этого commit.

## Что реализовано

- Общий `http.js`: cookie-сессия, `X-Requested-With`, JSON, `204`, ошибки
  валидации, сети, таймаута, неожиданных ответов и истёкшей сессии.
- Общий `app.js`: создание и редактирование подкаста, автозагрузка, создание
  эпизода по ссылке, редактирование эпизода на его странице, подтверждение
  удаления, запуск/отмена загрузки и запуск пересборки RSS.
- CSS-индикаторы ожидания, ошибки внутри форм/модалок, ссылка на вход при
  истечении сессии, управление фокусом и `prefers-reduced-motion`.
- Обновление именованных серверных фрагментов: карточки, заголовки,
  breadcrumbs, статистика, пустые состояния, метаданные и плеер. Формы
  редактирования не заменяются; плеер сохраняется при прежнем audio URL.
- Последовательный polling прогресса и RSS через 2 секунды с паузой в скрытой
  вкладке, увеличением интервала при сбое и запросом конечного состояния.
- Удалены обработчики-заглушки подключаемых операций; названия передаются
  через HTML data-атрибуты, сообщения выводятся через `textContent`.
- Исправлена генерация токенов новых media-файлов: используется
  `File.generate_token()`, совместимый с маршрутами выдачи аудио.
- Подготовлено отдельное приложение проверки `src/tests/browser_app.py`:
  реальная изолированная PostgreSQL и авторизация, fake-границы очереди,
  Redis, storage и источника медиа с задержками фоновых операций.

## Исправления после основного commit

- Повторные и конфликтующие операции блокируются до окончания обновления
  фрагментов, а не только до ответа изменяющего запроса. После истечения
  сессии повторная отправка формы также блокируется.
- Отложенное обновление конечного статуса сохраняется для следующего polling,
  если предыдущий refresh пересёкся с изменяющим запросом.
- Polling не применяет свой старый fragment-ответ во время изменения фильтров.
- При открытии диалога фильтров поля синхронизируются с текущим URL.
- Добавлены четыре регрессионных теста реальных обработчиков JS с небольшой
  DOM-заглушкой. Они дополняют 12 тестов HTTP-клиента; браузер не заменяют.

## Браузерная проверка и оставшаяся работа

Реальный браузерный проход **не выполнен**. Встроенный browser automation
завершается до получения UI: процесс Node не может прочитать
`/System/Library/OpenSSL//openssl.cnf` (`Operation not permitted`).
Playwright CLI запускает установленный Chrome, но браузер завершается с
`SIGABRT`; повтор после запроса расширенного доступа дал тот же результат.
Ранее установка Chromium была отклонена сетевой политикой (`403 Domain not
in allowlist`). Эти ограничения не обходились.

Диагностическая запись: `output/playwright/stage2-browser-blockers.txt`.
Скриншоты, трассы успешного прохода и проверка реального DOM отсутствуют.
Тесты с DOM-заглушкой не доказывают корректность рендера, загрузки аудио,
переходов фокуса или взаимодействия всех операций в браузере.

Реализация этапа 2 и доступные автоматические проверки готовы. Критерий
первичного браузерного прохода остаётся открытым. До завершения этапа 3
нужно восстановить работу браузерных инструментов, выполнить полный тестовый
набор и все согласованные браузерные сценарии на изолированных данных.
P6b (оставшиеся HTML views) этим этапом не закрывается.

Коммиты и push агент не выполнял. Этап 3 не начат; требуется подтверждение
пользователя с учётом незавершённой браузерной проверки.
